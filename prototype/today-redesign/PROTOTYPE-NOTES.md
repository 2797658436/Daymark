# 今日页改版原型（2026-10-27 ~ 10-28）

**状态**：**已实施**（2026-10-28）。生产代码在 `src/App.tsx` 的 `TodayPage`、`src/components/today/carry-over.tsx` 与 `src/styles.css` 的今日页段；真实行为以代码和测试为准，本文只记录设计取舍与踩过的坑。
**版本**：v2（`index.html` 已重做为 v2；v1 的「顶部状态条」方案已被用户否决，不再保留）

## 要解决的问题

同一批 `executionSessions` 在今日页被渲染了三遍（`src/App.tsx` `TodayPage`）：

| 根因 | 位置 | 现象 |
| --- | --- | --- |
| `sessions` 与 `missed` 是同一数组的两个切片 | App.tsx:898-899 | 已结束的时段既进「待回顾」卡片，又在时间线里带「待回顾」标签 |
| `nowState` 从 `sessions` 里挑一条放大 | App.tsx:932-957 | 顶部「现在」大卡与时间线当前行是同一个 session |
| `due` 只按截止日期筛，不看今天是否已排 | App.tsx:907 | 已排进时间线的任务在「临期」区再出现一次，连进度条也重复 |

附带问题：`onSkipReview` 把时段写成 `missed`，而时间线只渲染 `status === "scheduled"` —— 点了「本次未推进」，这件事就从时间轴消失，与「没干也可以留着」相反。

## v2 定下来的三条

1. **删除顶部「现在」状态条**。当前时段那一行/那一块自己承担：标题、剩余时间、进度、主操作全在行内。
2. **当前行整行放大**（A：标题 20px、行高约 96px；B：块 92px）。层级靠**行高差**建立，不再靠独立面板。
3. **已过时段留在原位**，行内「已过」+「记录实际／挪到之后」，不写 `missed`，不要求裁决。

### 空档场景（去掉状态条后最容易塌的地方）

- A：插入一个虚线橙框的「现在」行，写「这段时间是空的 · 下一次 22:45 开始，还有 8 小时」，配「安排一段」。
- B：空档带变成可选状态（虚线强调框 + 游标 + 同一句文案 + 按钮），不再只是灰条。

## 两套方案

### A · 列表轴

- 当前行放大，已过/未来的行紧凑。
- 有「现在 hh:mm」分隔线，切开已过与未来。
- 改动面：仅 `TodayPage` 内部结构 + 若干 `.today-*` 样式。日历组件不动。

### B · 真时间轴（流式分段）

- 轨道按真实时间比例排，无内容的长段折成「空档 13 小时 15 分」带。
- 游标是**指针式**：卡片几乎占满轨道宽度，横贯线会被卡面盖掉只剩一截像 bug，所以只画轨道左边缘 22px 短线 + 圆点，纵向位置表达「现在在块里的哪一段」。
- 代价：当前块要比按比例算出的高度多占 20px 才能放下操作，时间比例的「诚实」在最重要的那一块上打了折。空档带（64px）比 1 小时的已过块（58px）还高，比例同样失真。

## 去掉状态条之后新增的风险（必须在实施时解决）

**当前行不再保证在首屏。** 状态条的最大好处是「无论今天排了几段，现在永远在顶上」。A 方案里如果一天有 8 段，当前行可能在第 5 行。

两个解法，建议一起用：

1. 打开今日页时把当前行滚到视野中央附近（日历页已有同类要求，可直接复用 `scrollIntoView` 的锚点逻辑）。
2. 已过时段超过 2 段时，折叠成一条「上午 3 段已过」的摘要行（点开展开），让当前行自然上移。

## 场景数据（取自用户截图 10/27 23:26）

- **时段中**：08:30–09:30 Matplotlib 可视化 30%（已过）；22:45–23:45 写开题报告 45%（进行中，剩 19 分钟）
- **当前空档**：同一份数据，时钟改成 14:20；22:45 那段变成「未来」行，带「提前开始」
- 临期：写开题报告（逾期 2 天，今天已排）、实现数据采集模块（还有 6 天，今天未排）
- 待续：整理参考文献（昨天 14:00）、跑通数据清洗脚本（昨天 20:00）、读 3 篇论文（10/25）

## 已定：方案 A（2026-10-28）

用户选定 A。当天按截图复查后做了 4 处修正，`index.html` 里 A 的形态以这一版为准：

| 问题 | 改法 |
| --- | --- |
| 横向空白太大：已过行的进度条只占左半边，操作按钮在最右，中间空 400px | 普通行改**单行内联**（标题 + 状态 + 进度条 + 操作一行放完），行高从 76 压到 51px |
| 当前行三行信息摞在左侧，右边只剩按钮 | 当前行改**两行式**：① 标题 + 状态 + 剩余时间；② 进度条（max 480px）+ 主操作。空白被进度条吃掉 |
| 「现在 23:26」分隔线比当前行还抢眼，还把轨道切断 | **删掉分隔线**。「现在」由当前行的 chip + 橙色底 + 实心点表达，轨道保持连续 |
| 空档信息出现了两遍（空档行 + 底部提示） | 有当前时段时不显示空档行；空档行出现时不显示底部提示 |
| 页头统计行「2 段安排 · 1 段已过 · 现在进行中 · 2 项临期」是重复计数 | **整行删掉**。段数写进「今天」卡的头（2 段 · 1 段已过），临期和完成各有自己的数目，页头只留日期 + 打开日历 |

另外两处：

- **已完成移入右列**，与临期同宽（172px）堆叠。时间轴只留"今天排过的东西"，不再是「排过的」和「做完的」两套清单。完成项点击弹气泡看详情（含完成时间）。
- 空档行的轨道用**真实占位元素**画虚线，不能用 `::before` —— 后者在 grid 容器里会变成网格项，被塞进第一格（实测虚线跑到列 1 中间）。

## 浮钮归属（2026-10-28 二次修正）

产品里 `.task-pool-toggle` 是 `position:fixed; right:18px; bottom:18px; height:44px; z-index:31`（styles.css:388），只在**任务池收起时**出现（App.tsx:745 `{hasTaskPool && !showTaskPool && …}`）。初版原型把「待续」也放在右下 `right:24 bottom:24`，正好压住它 —— 是原型漏画了任务池浮钮，不是位置本身没问题。

定稿：

- **右下 = 任务池**（主入口，`--accent-strong` 文字）
- **左下 = 待续**（次级入口，`--text` 文字 + 橙色数字徽标），`left:88px`（导航 72 + 16）、`bottom:18px`、同样 44px 高，底边与任务池浮钮对齐
- 待续抽屉从**左下角**展开，`left:88px; bottom:74px`

理由：左＝回头看，右＝往前做，两者不抢位；而且不管任务池开还是关，待续的位置都固定。

实施时要注意 `styles.css:646-652` 那段 z-index 分层注释（31 任务池浮钮、32 回到现在），待续浮钮要新增一档并同步更新那段注释与 `e2e/phase1.spec.ts` 的遮挡判据。

**实施后的两处修正**（原型与真机的差距）：

- 右列从 172px 改为 **13rem（208px）**：16px 根字号下 172 装不下「实现数据采集模块」这 7 个字。
- 三张卡统一 `padding: 0` —— `.surface-card` 的 `18px 20px` 套在右列上会再吃掉 40px，任务名只剩 3 个字。

## 与现有规范的冲突（实施时要改）

- `docs/design/UI-SPEC.md` §主窗口结构「今日页『现在』模块……不可隐藏」—— v2 把它**降级为时间轴上的当前行**。不可隐藏的原则保留（当前行始终存在且高亮），但"模块"这个词要改，否则一行代码都动不了。
- `docs/design/UI-SPEC.md` §今日页「页面最醒目的『现在』模块始终只呈现当前最需要决定的状态」—— 要改写成"当前行"的措辞，并把"空档时由虚线『现在』行承担"写进去。
- `docs/design/UI-SPEC.md` §今日页「待回顾任务排列在『现在』模块之后」—— 已过时段回到时间轴原位，这句要重写。
- `docs/design/UI-SPEC.md` §今日页「顶部只显示日期、今日总进度条和临期任务数量」—— 现在**页头顶部只剩日期和「打开日历」**，所有计数下放到各卡片头（今天 / 临期 / 今天完成）。总进度条仍未实现，这条要按 A 的形态重写。
- `docs/design/UI-SPEC.md` §今日页「已完成任务默认折叠在底部」—— A 已把它移到右列（与临期同宽），这条要改写。
- `CONTEXT.md` 的「未执行时段」词条仍成立：时段不写 `missed` 只是不再由用户手动裁决，历史里依然是「已过去但没产生实际投入」。
- `onSkipReview` 在日历页也有入口（App.tsx:719），按本方案只在今日页移除，日历页的待回顾流程保持不变。
