# Issue tracker: GitHub

Issues and product specifications for this repository live in GitHub Issues at `2797658436/Daymark`. Use the `gh` CLI from this checkout so the repository is inferred from `origin`.

## Conventions

- Create specifications and work items as GitHub issues.
- Read an issue together with its labels and comments before acting on it.
- Apply and remove the mapped triage labels recorded in `triage-labels.md`.
- Close an issue only after its stated acceptance criteria have been met.
- External pull requests are not treated as feature-request or triage inputs.

When a skill says to publish to the issue tracker, create a GitHub issue. When it says to fetch the relevant ticket, read the corresponding issue and its comments.
