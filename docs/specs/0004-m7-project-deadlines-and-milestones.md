# M7：项目截止日期与项目里程碑

## Problem Statement

阶段 3 M6 已经建立周视图全天区、月视图摘要和统一日期详情，但 SQLite schema v5 只有任务截止日期。`UI-SPEC.md` 需要项目截止旗帜与里程碑菱形；若把它们临时放入设置、前端内存，或从最后一个子任务截止日期推导，会丢失项目本身的约束语义，也无法可靠备份、查询和验证。

## Solution

M7 把项目截止日期和项目里程碑建立为第一等核心事实，并分四段交付：

1. **M7.1 核心数据**：schema v6、模型、工作区快照、原子 CRUD、浏览器预览适配、备份兼容和迁移测试。
2. **M7.2 项目编辑**：项目卡与详情可编辑截止日期，并可新增、编辑、删除多个里程碑及其唯一达成条件。
3. **M7.3 日历标记**：复用 M6 日期标记接缝，在周视图显示项目截止旗帜与里程碑菱形，在月视图和右侧详情中按现有优先级呈现。
4. **M7.4 历史与风险**：保存到期时的目标和实际结果，提供未达成后的显式续排入口，并让确定性排程与风险提示读取项目约束。

## Domain Model

### Project deadline

- `Project.deadlineLocal` 是可空的本地自然日，表达整个项目希望完成的日期。
- 它不等于任一子任务截止日期；修改项目截止日期不会静默修改子任务或执行时段。
- 一个项目同时最多有一个当前项目截止日期。

### Project milestone

- 一个项目可以有多个里程碑；每个里程碑包含标题、目标本地自然日、稳定排序值和且仅一个达成条件。
- `orderedTask`：目标任务必须属于同一项目；当前结果按该任务及排序在它之前的任务是否全部完成判断。
- `taskCount`：目标数量必须大于 0；当前结果按项目已完成任务数量判断。
- `projectProgress`：目标进度必须为 1–100；当前结果读取现有耗时加权项目进度。
- 条件类型之外的目标字段必须为空，避免一条里程碑同时出现多套互相矛盾的目标。

## M7.1 Acceptance Criteria

- schema 从 v5 单事务迁移到 v6；旧项目的 `deadline_local` 默认为空，旧工作区的里程碑集合为空，既有事实不丢失。
- `projects` 增加可空 `deadline_local`；`project_milestones` 使用项目外键，并以数据库 `CHECK` 保证三种条件恰好一种有效。
- 原生模型和 TypeScript 模型使用同一 camelCase 边界；`WorkspaceSnapshot` 同时返回项目与里程碑。
- 更新项目、创建／更新／删除里程碑都经过后台串行写队列；成功后返回新快照并刷新当日备份。
- 数据库拒绝无效日期、空标题、跨项目目标任务、零／负任务数量、范围外进度，以及条件类型与目标字段不匹配的数据。
- 浏览器预览对旧 localStorage 补齐 `deadlineLocal: null` 和空里程碑集合，并提供与桌面端一致的基本校验和 CRUD 语义。
- v1–v5 备份仍可检查并在恢复后迁移；标记为 v6 的备份缺少 `project_milestones` 时必须拒绝。

## M7.2–M7.3 Acceptance Criteria

- 新建和编辑项目可填写或清除项目截止日期；项目卡明确显示截止状态，不把它展示成子任务截止。
- 项目中可以新增、编辑、删除多个里程碑；表单随条件类型只显示对应目标输入，并在保存前给出可读摘要。
- 周视图项目截止使用旗帜、里程碑使用菱形；月视图与日期详情保留不同文字／图标语义，不只依赖颜色。
- 点击项目截止或里程碑标记打开对应项目详情并保留日期选中态；标记不占用时间，也不创建执行时段。

## M7.4 Acceptance Criteria

- 后台在读取工作区和执行领域写入前，以设备当前本地自然日检查里程碑；只有目标日期已经过去且仍未达成的里程碑才冻结一次结果快照，同日不提前冻结，已经达成的不生成失败快照。
- `orderedTask` 的达成判断覆盖目标任务以及项目排序中位于它之前的全部任务；前置任务未完成时，即使目标任务已完成也仍视为未达成。
- 已冻结里程碑属于历史记录，不能再编辑或删除；用户只能通过显式“续排”创建新的当前里程碑，原里程碑和结果快照保持不变。数量与进度条件保持累计目标语义，不能把差额误写成新的累计目标。
- 自动排程优先使用任务自己的截止日期；任务没有截止日期时，读取仍未达成且适用于该任务的最早里程碑日期，并与项目截止日期取更早者。数量条件按排序选择达到累计目标仍需完成的任务，进度条件约束项目中的活动任务。项目卡用明确文字显示逾期、今日到期或剩余天数，作为本阶段的项目风险提示。
- 首次冻结结果属于核心数据变化，必须刷新当日备份；schema v7 备份必须包含 `milestone_outcomes`，旧版本备份仍按版本感知规则检查和迁移。

## Data and Safety Decisions

- 核心事实只存 SQLite；Tauri Store 继续只保存界面偏好。
- 不创建通用 `calendar_events` 表。日历标记由任务、项目与里程碑事实组成只读投影。
- M7.1 的 CRUD 不自动更改任务、任务截止日期、执行时段或进度历史。
- SQLite 迁移、领域写入和备份恢复继续使用现有事务与写后备份协议。

## Out of Scope for M7

- 不做基于总容量的项目完工预测、里程碑专属排程按钮、节奏建议或自动级联顺延；本阶段只把任务截止、适用里程碑日期与项目截止作为确定性排程约束。
- 不为项目截止日期或里程碑新增系统通知。
- 不改变项目进度的既有耗时加权定义。
- 不新增通用日历事件、云同步或协作对象。
