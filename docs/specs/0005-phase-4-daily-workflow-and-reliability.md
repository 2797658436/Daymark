## 1. 目标与阶段边界

本阶段让用户能连续完成“找到需要关注的事项 → 小范围编辑 → 安排执行 → 查看实际推进 → 返回原位置”。优先补齐既有交互与数据呈现，控制新增核心事实的范围。

### 1.1 必须交付

| 模块 | 结果 | 优先级 |
| --- | --- | --- |
| M8 气泡与编辑会话 | 添加里程碑、任务等继续采用紧凑气泡；统一键盘、草稿、提交与失败行为 | P1 |
| M9 日历浏览状态 | 日／周各自记住浏览位置，缩放、连续跨日、拖拽与目标跳转不互相抢滚动 | P1 |
| M10 截止事项视图 | 在一个入口查看任务截止、项目截止与里程碑，按事实进入编辑或安排 | P2 |
| M11 日／周／月回顾 | 用相同统计口径查看成果、净进度变化、实际投入与待续，支持明细下钻 | P2 |
| M12 长列表与错误反馈 | 常用操作在长课程、高缩放和慢请求下保持可用，错误可恢复 | P1 |
| M13 桌面与发布验收 | 验证 Windows 实际运行、备份恢复、旧设置兼容和真实使用，交付可追溯安装包 | P1 |

P1 表示范围重要性，不是交付顺序——实际交付顺序以第 10 节的依赖链为准（M10、M11 虽标为 P2，其工作包仍排在 M12 之前）。标注 P1 不意味着已确认当前存在严重故障。S0–S3 缺陷等级沿用真实使用验证方案。

### 1.2 本阶段不交付

- 暂停／恢复项目、删除后保留历史、基于历史重新开始、自动级联顺延。这些涉及生命周期、历史快照及事务，须单独立项；类型中已有 `paused` 不等于完整流程已交付。
- AI 规划、云同步、账号、多设备、复杂重复规则、项目完工预测和自动修改截止日期。
- 满意度、感受标签、分类新模型，以及 PNG／CSV 回顾导出。现有 UI 规范包含这些长期目标，本阶段只交付已有事实能支持的回顾子集。
- 开机自启、全局快捷键、通知卡片点击路由等新增系统集成。本阶段验证现有提醒与托盘恢复，不假设系统通知具有现有 API 未提供的能力。
- 磁盘草稿恢复、崩溃后恢复未提交编辑、完整只读安全模式。这些需要独立持久化和恢复协议。

### 1.3 不可破坏的约束

计划时段、实际执行和手动进度始终分离。时间流逝不自动记为未推进；实际投入不自动增加进度。里程碑到期结果不能被后续修改改写。批量排程继续原子应用、整体撤销。所有核心写入保留原生串行队列与写后备份。SQLite 保持 schema v7，本阶段不新增迁移。

## 3. 用户路径与界面原则

| 路径 | 预期操作 | 完成后位置 |
| --- | --- | --- |
| 项目内添加任务／里程碑 | 点击入口 → 气泡填写 → 保存 | 原项目行保持可见，新对象显露 |
| 编辑失败 | 显示字段或提交错误 → 修正／重试 | 相同草稿、相同对象、相同气泡 |
| 从今日进入某次安排 | 点击安排 → 切到正确日期并显露 | 目标优先于记忆位置 |
| 日切周再切日 | 保存逻辑时间位置 → 恢复对应视图 | 原日期与可见时间附近 |
| 查看截止事项 | 筛选 → 查看对象 → 编辑或安排 | 返回后保留筛选与列表位置 |
| 回顾某日 | 选周期 → 点日期／任务 → 看原始明细 | 返回保留周期、筛选和焦点 |

小型编辑不使用撑开主页面的大卡片。桌面气泡默认宽度沿用约 23rem、复杂预览约 44rem，最大不超过视口减 24px；上下边界各至少 12px。高缩放允许内部滚动，提交区可达。恢复等危险操作继续使用独立确认模态。

主题沿用暖杏语义变量；状态不能只靠颜色。新增导航使用“截止事项”，其余入口保留现有标签“今日／日历／项目／7 天回顾／数据／设置”（末项标签是“设置”，其 `PageId` 仍为 `appearance`）；M11 落地后“7 天回顾”这一标签须随日／周／月周期一并改为与周期选择一致的措辞。新增入口后重新检查最小窗口高度与 200% 缩放，必要时导航自身可滚动，不能隐藏关键入口。

## 4. M8：气泡和编辑会话

### 4.1 统一语义

定义两类浮层：只读信息气泡为非模态，可外点关闭；含保存／取消的编辑气泡为紧凑模态，背景保持可见但不可交互。编辑气泡使用 `role="dialog"`、`aria-modal="true"`、标题关联、Tab 循环与焦点恢复。视觉上仍是锚点附近的小气泡，不加大型居中表单。

编辑气泡外部点击不保存、不丢弃、不触发背景操作。取消或 Esc 是明确的放弃本次编辑动作；未提交修改不会写入数据库。已有导入流程“取消保留按模式草稿”的行为是显式例外，继续保留并写入测试。提示文案要区分“取消编辑”与“关闭并保留导入草稿”。

打开编辑气泡时，通过统一浮层宿主将应用背景设为 inert；关闭时恢复原状态。宿主位于 body 的 Portal 中，不能被一起 inert。只有顶层浮层处理 Esc；本阶段不允许编辑气泡嵌套另一个编辑气泡，子步骤使用同一面板切换。原有恢复模态须复用宿主管理或明确排他，不能出现一个浮层关闭后解除另一个浮层的背景保护。

### 4.2 拟议契约

```ts
type EditorPhase = "editing" | "submitting" | "error";
type CloseReason = "cancel" | "escape" | "saved";
interface EditorSession<T> {
  key: string;                // 对象类型 + ID；新建使用独立临时 ID
  initial: T;
  draft: T;
  phase: EditorPhase;
  error: string | null;
  trigger: HTMLElement | null; // 仅内存，不进入 Store
}
```

拟提取 `useEditorSession` 管理草稿与请求，`FloatingPanel` 仅负责位置、焦点和显示。显式传入 `busy` 与关闭策略，不再查询后代 `[aria-busy=true]` 猜测业务状态。表单提交仍调用原有 NativeApi，不引入新的保存协议。

### 4.3 状态转换

| 当前状态 | 事件 | 结果 |
| --- | --- | --- |
| editing／error | 修改字段 | 更新 draft；清理对应字段错误 |
| editing／error | 提交，校验失败 | 留在原处，聚焦首个错误字段 |
| editing／error | 提交，校验通过 | 同步锁定 submitting，再发出一次请求 |
| submitting | 连点保存、Enter、Esc、取消 | 不创建第二请求，不关闭 |
| submitting | 成功 | 应用返回快照，关闭并显露保存对象 |
| submitting | 失败 | error，草稿原样保留，允许重试 |
| editing／error | 取消或 Esc | 按该编辑器的明确草稿策略关闭 |
| editing／error | 工作区重新载入或数据恢复 | 在当前会话内明确放弃或返回，不静默丢弃草稿 |
| submitting | 工作区重新载入或数据恢复 | 等待请求结果，不关闭、不重发 |

请求闭包保存 session key；旧请求不得关闭或覆盖另一对象的编辑器。数据恢复或工作区重新载入必须先检查活动编辑会话：未提交时在当前会话内明确放弃或返回；提交中等待结果。应用退出时的跨进程草稿保护不在本阶段承诺内。

触发元素被筛选移除时，关闭后依次聚焦同项目添加入口、页面标题（可程序聚焦）、主内容区，不调用已断开节点。中文输入法组合期间 Enter 不提交，Escape 优先交给输入法，避免关闭整个编辑器。

## 5. M9：日历浏览状态与滚动协调

### 5.1 保存逻辑坐标

禁止直接跨视图复用 `scrollTop`。日视图有三日缓冲和折叠区间，周视图有全天区，相同像素并不表示相同时间。

```ts
interface CalendarPosition {
  date: string;               // 合法本地日期
  minute: number;             // 0 <= minute < 1440
  viewportRatio: number;      // 该时刻在可见高度中的比例，0..1
}
type CalendarPositions = {
  day: CalendarPosition | null;
  week: CalendarPosition | null;
};
```

先以 App 层内存保存（切页仍在），通过全部回归后再接入 Store。月视图不存时间轴坐标，沿用日期锚点并在进入时置顶。

位置采样选视口中心对应的日期／分钟；恢复使用当前 `calendarTimeline` 映射重新计算像素。中心命中折叠条时取其时间区间中点，不因恢复而展开整段非默认时间。用户原有临时展开仅在当前会话保留，不写入偏好。

### 5.2 单一滚动仲裁

拟提取 `useCalendarViewport`，使以下请求经过同一入口，按优先级执行一次：

1. 正在进行的拖拽／拉伸及其自动滚动拥有控制权；其他恢复延后。
2. 用户明确的“回到现在”、目标 session 路由、键盘显露。
3. Ctrl+滚轮的指针时间锚点补偿。
4. 连续日三日缓冲平移的坐标补偿。
5. 进入视图时恢复记忆位置。
6. 无记忆且日期包含今天时首次定位当前时间；非今天回退日首个默认时段，无时段时 09:00。

拖拽结束后重新判断待处理请求是否仍属于当前视图。每次视图／日期变更递增 generation；过期 animation frame 和 ResizeObserver 回调不得再改新视图。程序性滚动不立即触发偏好保存，用户滚动停止 300ms 后采样，切页时刷新最后一次内存值。

若布局尚未测量，等待实际轨道可测量后恢复；不依赖固定延时猜测 DOM 完成。连续跨日更新后的 date 与三日缓冲同步；周位置的 date 不属于当前周时，使用当前周锚点及原 minute。

### 5.3 验收阈值

固定窗口与布局下，恢复逻辑时间误差不超过 1 分钟或 2 CSS px（取可测量的较宽容阈值）；重复日↔周切换 10 次不得累计漂移。缩放前后指针时间保持不变，且所有计划对象序列化结果完全一致。窗口尺寸变化时以时间保持为准，不要求旧像素相同。

不得重新添加全局 `overflow: clip` 或关闭浏览器锚定来掩盖缺陷。缩放档位与连续范围提取到同一配置源，使校验范围、回退预设与界面预设三者互洽，确保每个预设经规范化、保存、重载仍保持同值；必须先解决“月视图 detailed 预设 160 超出规范化上界 132、且回退路径同样越界”这一矛盾，否则 AC07 无法通过。具体数值以基线 UI 与回归验证确定后记录。

## 6. M10：截止事项集中视图

### 6.1 数据投影

新增纯函数 `buildDeadlineItems(workspace, today, filter)`，由现有快照生成记录，不建立截止事项表。

```ts
interface DeadlineItem {
  key: string; // kind + sourceId
  kind: "task" | "project" | "milestone";
  sourceId: string;
  projectId: string | null;
  date: string;
  title: string;
  state: "open" | "currentlyReached" | "frozenUnmet";
}
```

分组：已逾期、今天、未来七天、以后；“未来七天”为 tomorrow 至 today+7，边界用本地日期运算，禁止除以固定 24 小时推算夏令时日期差。排序为日期升序、类型固定顺序（任务／项目／里程碑）、原 sortOrder、稳定 ID。

任务默认显示 active 且具有截止日期的普通任务，排除习惯内部任务；可显式显示 completed／paused，不能把暂停对象重新安排。项目显示其声明的截止日期，不以子任务最后日期替代；没有项目完成字段，因此显示“当前任务 N/N 已完成”，不声称项目历史上完成。无任务项目仍可显示截止日期。

里程碑优先读取冻结结果。没有冻结结果时按 M7 同一规则派生当前是否达成；冻结未达成的记录保留“到期未达成”，即使现在已推进也不改写。默认显示 open 与 frozenUnmet，可切换显示当前达成项。项目项不通过任务达成计数自动隐藏。

### 6.2 页面与动作

提供类型、项目、状态、关键字筛选和日期分组；搜索不改变原对象排序与内容。无数据和筛选无匹配使用不同空状态，后者提供清除筛选。

任务动作复用编辑气泡和预选任务的排程入口；项目动作定位项目；里程碑动作定位项目内具体目标，冻结目标只有查看／续排。选择安排后仍显示现有草案并确认，不能直接写入时段。返回列表后恢复原筛选、焦点项和滚动；源对象不存在时刷新列表并显示中性提示。筛选、焦点项与滚动位置沿用 M9 的过渡策略，先以 App 层内存保留：同一会话内跨页返回仍然有效，应用重启后不恢复；它们不写入 Store，也不与搜索文本一并保存。AC10 据此按“同会话跨页返回”判定，重启恢复不在本阶段范围。

新增 `PageId = "deadlines"`，必须同步修改三处重复定义合法值的来源：`src/lib/settings.ts` 的 `PageId` 联合类型、同文件 `normalizeSettings` 中 `lastPage` 的硬编码 `isOneOf` 数组（该行另含 `"overview" → "today"` 历史别名）、以及 `src/App.tsx` 的导航 `pages` 表。只改类型而不改校验数组会出现类型检查通过、运行期被静默回退到默认页的故障，须以设置规范化测试覆盖三处一致。任务详情仍使用原始 ID，禁止把派生 DeadlineItem 当作可直接保存对象。

## 7. M11：日／周／月回顾引擎

### 7.1 周期与接口

```ts
type ReviewPeriod = "day" | "week" | "month";
interface ReviewQuery {
  period: ReviewPeriod;
  anchorDate: string;
  projectId: string | null;
}
// 拟议纯接口；now 显式注入，避免页面间计算时钟不同。
// buildReview(workspace, query, now) -> ReviewResult
```

日为一个本地自然日；周为周一至周日；月为自然月，不等于最近 30 天。首次进入默认当前周，此后记住周期和锚点；从某日进入则临时聚焦该日，明确更新当前查询。日期运算使用日历加减，不用固定毫秒增减月份。

### 7.2 统一统计口径

| 指标 | 计算规则 | 呈现规则 |
| --- | --- | --- |
| 净进度变化 | 周期内事件逐条求 `toProgress - fromProgress`，包含下调 | 单位百分点，可负；跨任务合计不叫完成率 |
| 曾完成任务数 | 周期内至少一次 toProgress=100，按 taskId 去重 | 与当前 progress 分开；重复完成不重复计数 |
| 有进度变化任务数 | 周期内存在事件，按 taskId 去重 | 净变化为零仍可有变更明细 |
| 已记录实际投入 | 已结束记录与周期各日本地时间窗口的交集时长 | 按 UTC 毫秒求交、日界转换为 UTC；跨日分别计入 |
| 进行中的执行 | 没有 actualEndUtc 的记录单独列出 | 不混入已确认投入；可显示“进行中”而非精确最终数 |
| 待回顾 | scheduled 已结束、任务未完成、无执行记录 | 派生状态，不写 missed；与 App 共享同一判断 |
| 明确未推进／跳过 | 读取 session／habit occurrence 的显式状态 | 关联发生项与 session 去重；取消安排与跳过分别说明 |
| 待续 | 当前 active，周期内有未完成推进或待回顾／未推进／跳过事实 | 按任务去重；只提供查看或安排，不复制任务 |

实际投入保留毫秒或秒精度至汇总结束，再转换显示分钟；避免逐条四舍五入后累积偏差。旧并行执行记录按记录投入相加，标注“执行记录累计”，不称唯一墙钟时间。相同 ID 去重，不按标题去重。无实际记录显示“未记录”，有计划仍显示计划，不伪造 0% 执行率。

UTC 事件按查看时设备本地时区分桶，并显示当前时区说明；计划继续按已保存 localDate 展示。当前模型没有每次进度事件的历史本地时区快照，因此不承诺跨设备时区查看时日分桶完全不变。旧计划未知 UTC 偏移保持未知。

单任务进度起止仅在事件证据支持时显示：周期内第一条 fromProgress 与最后一条 toProgress；无事件显示“本周期无进度记录，当前 N%”，不从当前值反推历史。排序使用发生时间与稳定 ID，同一时刻存在无法证明先后的事件时保留明细，不假造精确先后。

### 7.3 数据例子与边界验收

- 23:50 至次日 00:20 的已结束记录：前日 10 分钟，次日 20 分钟；跨月同理。
- 同日 40→100→60：净变化 +20 百分点，曾完成 1 项，当前 60%；不得显示当前已完成。
- 任务 A +40、任务 B -10：合计 +30 百分点；不能显示项目完成度 30%。
- 只有已结束计划没有实际执行：显示待回顾和“实际未记录”，不新增 missed。
- 已冻结的里程碑未达成结果：保留当时结果；后续完成不会重写该周期快照。

### 7.4 页面和下钻

页面顺序为成果与待续 → 投入和进度图 → 任务／项目明细。周显示七日图，月显示自然月日期概览；净负进度具有零基线与文字，不用正向热度暗示。投入图只用分钟，进度图只用百分点。

点击或键盘激活日期、项目、任务，打开页面内明细区，显示原始事件时间、进度变化、实际起止和已记录备注。回到汇总保留查询与滚动。所有图表有等价数值表，不依赖悬停。未知对象引用显示“来源不可用”及保留的事实，不让整个页面崩溃。

先保留 `buildSevenDayReview` 作为兼容入口，迁移调用者到新引擎后移除。月历摘要、今日待回顾、回顾共享底层事实选择器；不能维护三份不一致算法。

## 8. M12：长列表、错误和响应性

先建立任务／项目／session／record 索引，每次 workspace 快照变更重建一次；避免列表每行重复扫描全量数组。筛选与展示用稳定 ID，保存后只在确有需要时显露目标，禁止每次状态更新滚回顶部。

性能样本：100 项课程、1,000 项任务、10,000 条混合历史记录，固定随机种子与测试机器信息。拟定预算：搜索输入到列表稳定显示 P95 ≤200ms，气泡打开 ≤150ms，月回顾计算 ≤100ms（预热后 20 次，生产构建，记录机器与数据规模）。这些是验收目标，不是当前测量结果；若不达标先查重复计算，再决定分页或虚拟列表。虚拟化必须保留键盘遍历、最近推进定位、拖拽来源和屏幕阅读器名称。

保存中显示动作进度；失败用局部持续错误和重试，设置失败保留“未保存”与重试，不被旧请求成功覆盖。网络导入按请求编号丢弃过期结果，取消读取不误报最终数据库提交已取消。写入开始后沿用不可取消与单事务边界。

备份逐条检查保留只读协议；增加缓存与可见项调度时，以 path+mtime+size 为缓存键，恢复确认前重新 inspect。不得把缓存成功结果视为来源文件永久有效，也不并行绕过原生数据操作队列。

## 9. 模块划分与兼容策略

拟议新文件（尚不存在，实施时再创建）：

| 文件／目录 | 责任 | 禁止承担 |
| --- | --- | --- |
| `src/components/ui/overlay-host.tsx` | 顶层浮层、inert 与焦点所有权 | 业务保存、数据库写入 |

| `src/lib/deadlines.ts` | 截止事项投影与筛选 | 新增截止数据模型 |

| 现有 `src/lib/review.ts` | 周期引擎与明细聚合 | 自动生成用户进度 |

App 保留应用初始化、工作区命令协调、设置保存、页面路由和全局执行状态。每次只提取一个已验证边界，禁止同时重命名全量文件、修改布局与改写业务。

新增偏好：`calendarPositions` 默认日／周 null；`reviewPeriod` 默认 week；`reviewAnchorDate` 默认 null。PageId 增加 deadlines。字符串日期须真实有效，分钟／比例须 finite 且在范围内；未知字段忽略。搜索文本、未提交草稿、DOM 引用、临时展开、请求状态不保存到 Store。截止页的筛选、焦点项与滚动位置同样不进入 Store，仅按 M9 的过渡策略保留在 App 层内存。

旧设置／旧备份缺少新字段时使用默认值。恢复偏好后使内存浏览位置与新设置一致，清理旧筛选缓存和已结束编辑会话。新设置随现有 backup_preferences 一并备份，不扩充 SQLite 核心表。旧应用读取新偏好可能忽略新增字段，故回退后允许丢失新浏览偏好，不允许丢失核心事实。

本阶段不新增 Tauri Command 或依赖。如果实现发现必须新增导出、系统注册或磁盘草稿能力，应先修改范围并独立评审，不能当作内部细节顺手加入。

## 12. 验证、发布与回退

开发时按变更运行纯函数／组件或对应 E2E；所有工作包完成后串行运行：

```powershell
npm run check
npm run tauri build
git diff --check
```

`check` 已包含生产前端构建、Vitest、Playwright、Rust。不要同时运行 check 与 Tauri 打包，避免 Vite 生命周期和机器资源干扰。记录实际数量与日志，不要求为追求数量编写镜像测试。

发布前在独立 Windows 账户或明确隔离数据环境完成：旧 v7 备份恢复、缺少新偏好的恢复、损坏备份拒绝、恢复偏好失败回滚、实际托盘与提醒、升级后重新启动。不能在唯一的个人数据库上覆盖恢复来获取测试证据。

交付记录应包含：提交、未提交改动清单、是否推送、测试环境和实际结果、安装包路径与 SHA256、已知缺陷、截图、回退方法。版本号若调整，同步 package.json、Cargo.toml、Tauri 配置及锁文件相关版本；先确认原有 Cargo.toml 改动归属。

因为 schema 不变，回退使用上一份已验证安装包；先手动备份当前数据与设置，退出托盘进程，再替换版本。旧版本可能忽略新增偏好，但不应改变核心数据。发布前必须实测往返兼容，不能仅凭 schema 相同宣布安全。

S0 数据安全问题立即停止发布；S1 核心流程阻断或统计事实错误必须修复复测。S2／S3 记录影响、替代路径和后续任务，不把工程通过等同于真实使用成功。

真实使用继续沿用 [21 天验证方案](../reports/phase-2-21-day-validation-plan.md)，记录候选版本与变更日期；未提供 Day 0／每日记录／Day 21 证据时，状态为“待真实使用验收”。中途升级需标明版本区间，不能把不同版本的行为当成同一个固定样本。
