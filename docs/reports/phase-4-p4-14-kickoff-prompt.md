- 三块全空（例如「本周全部做完」）→ 卡片只剩标题 + 一行说明，**仍然渲染 `.review-outcomes`**（页面顺序断言依赖它存在）。

`.review-outcome-grid`：


### 3.4 继续推进：把已经算好的理由用起来

`review.ts:397-401` 已经给每个任务算了 `carryoverReasons`（`incompleteAdvance` / `pendingReview` / `notAdvanced` / `skippedOccurrence`），页面**一个字都没用**（只在明细 `review-detail.tsx:147` 里露过面）。

- 块内第一行加**理由摘要**：`1 项进度未走完 · 1 项计划未做`。
- 胶囊列表按理由优先级排序（`pendingReview` > `notAdvanced` > `skippedOccurrence` > `incompleteAdvance`），上限仍用 `CARRYOVER_PREVIEW = 6`。
- ⚠️ **文案不能直接搬明细那一份**：`review-detail.tsx:54` 的 `CARRYOVER_REASON_LABEL` 是**长句**（`周期内有未完成的进度推进`、`有已结束但还没有记录的时段`），放进摘要行会撑成两行；而且它是模块内 `const`，没有导出。做法：在 `review.ts` 里同时导出**长句表**与**短标签表**（`进度未走完`／`有待回顾`／`计划未做`／`跳过的习惯`），`review-detail.tsx` 改成 import 长句表、摘要用短标签表 —— **一个 `reason` 的两种文案必须住在同一个模块里**，别在两个文件各写一份（本仓护栏会抓重复实现）。
- 理由摘要的统计在 `review.ts` 里算（新增派生值），**不要在组件里 `filter` 一遍** —— 「需要新派生值就加进引擎」是这一页的既有约定。
- 摘要行同时受「一行放得下」约束：400px 列宽下 4 类理由全满会换行，**超过 2 类时只列前 2 类 + `等 N 类`**（N = 剩余类数），实测宽度写进报告。

### 3.5 里程碑：达成态不只靠色差

现在 `.review-tag`（`--muted`）与 `.review-tag.is-unmet`（`--muted-strong`）**几乎同色**，全靠文字区分。加图标区分（`lucide-react` 已在依赖里，别引新包）：达成 → `Check`，未达成 → `CircleAlert`。

⚠️ **不许引入「失败红」**。`CONTEXT.md` 与 UI-SPEC 都写了「未完成内容以待续呈现，不使用失败或惩罚性语言」，这一条比对比度更硬。

### 3.6 层级与外观一致性

- `h3`（`.82rem`）与正文（`.78rem`）差 0.04rem，视觉上分不开。块标题提到 `.84rem` + 600 字重，计数用 `.72rem` + `--muted` 跟在后面。
- 现在同一块里混了三种交互外观：任务胶囊（`.review-task-chip`，可点）、里程碑名（`.review-inline-link`，可点）、状态（`.review-tag`，不可点）。**要求**：可点的只有两种（胶囊 = 任务，文字链 = 项目／里程碑），纯展示只用 `.review-tag`；三者都要有可见的 `:focus-visible` 环。检查后**在报告里说明现状与是否改动**，不要默默不动。

### 3.7 待回顾条目补时长（可选，P1）

现在条目只有「任务名 + `10月19日 09:00–10:00`」。补一个时长（`60 分钟`）能直接回答「现在要不要处理」。**派生值加进 `review.ts`**（例如 `ReviewSessionFact` 上给 `durationMinutes`），不在组件里减时间戳。若判断成本高于收益，可以不做，但要在报告里写清理由。
