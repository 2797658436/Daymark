## 交付范围（只做这些）

### 1. 周期引擎（`src/lib/review.ts` 重写／扩展）

```ts
type ReviewPeriod = "day" | "week" | "month";
interface ReviewQuery { period: ReviewPeriod; anchorDate: string; projectId: string | null }
buildReview(workspace, query, now) -> ReviewResult   // now 显式注入，纯函数
```

- **周期口径**：日 = 一个本地自然日；周 = 周一至周日；月 = 自然月，**不等于最近 30 天**。日期加减一律走**日历运算**（`Date.UTC` 整数加减或既有 `addLocalDays` 之类），**不得用固定毫秒增减**（月份、闰年、夏令时会错）。
- **`now` 显式注入**：页面之间不得各算一次时钟；引擎内不读 `Date.now()`／`new Date()` 取「现在」。
- **`projectId` 过滤**：非空时只统计该项目的任务与其时段／记录；为 null 时统计全部。

### 2. 统一统计口径（规格 §7.2 的九行表格，逐行实现）

| 指标 | 必须做到 |
| --- | --- |
| 净进度变化 | 周期内事件逐条求 `toProgress - fromProgress`，**包含下调**；单位百分点、**可负**；跨任务合计**不叫完成率** |
| 曾完成任务数 | 周期内至少一次 `toProgress = 100`，按 `taskId` 去重；与当前 `progress` **分开**；重复完成不重复计数 |
| 有进度变化任务数 | 周期内存在事件，按 `taskId` 去重；净变化为零仍可有变更明细 |
| 已记录实际投入 | 已结束记录与周期**各日本地时间窗口的交集**时长；按 UTC 毫秒求交、日界换算成 UTC；**跨日分别计入** |
| 进行中的执行 | 没有 `actualEndUtc` 的记录**单独列出**；不混入已确认投入；可显示「进行中」而非精确最终数 |
| 待回顾 | `scheduled` 已结束、任务未完成、无执行记录 —— **派生状态**，不写 `missed`；**复用 `workspaceSelectors` 的同一判断** |
| 明确未推进／跳过 | 读取 session／habit occurrence 的**显式**状态；关联发生项与 session **去重**；「取消安排」与「跳过」分别说明 |
| 待续 | 当前 `active`，周期内有未完成推进或待回顾／未推进／跳过事实；按任务去重；只提供查看或安排，**不复制任务** |

- **精度**：实际投入保留毫秒／秒精度至汇总结束，再转换显示分钟；**不得逐条四舍五入后累积**（现在的实现正是逐条 `Math.round` 再相加，是错的）。
- **旧并行记录**：按记录投入相加，标注「执行记录累计」，**不称唯一墙钟时间**。
- **去重**：相同 ID 去重，**不按标题去重**。
- **无实际记录**：显示「未记录」；有计划仍显示计划；**不得伪造 0% 执行率**。
- **时区**：UTC 事件按**查看时设备本地时区**分桶，并显示当前时区说明；计划继续按已保存 `localDate` 展示。当前模型没有每次进度事件的本地时区快照，**不承诺**跨设备时区查看时日分桶完全不变。旧计划未知 UTC 偏移保持未知。
- **单任务进度起止**：仅在事件证据支持时显示（周期内第一条 `fromProgress` 与最后一条 `toProgress`）；无事件显示「本周期无进度记录，当前 N%」，**不从当前值反推历史**。
- **排序**：使用发生时间与稳定 ID；同一时刻无法证明先后的事件保留明细，不假造精确先后。
