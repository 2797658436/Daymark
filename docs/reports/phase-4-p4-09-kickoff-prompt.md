## 交付范围

### 1. 性能测量（AC15）

- 生成样本：`node scripts/fixtures/perf-sample.mjs --out output/perf-sample.json --anchor <固定日> --seed <固定种子>`（默认就是规格 §8 的 100 课程 / 1,000 任务 / 10,000 条混合历史）。
- **必须用生产构建测**：先 `npm run build`，再让测量指向 `vite preview`（或等价的静态服务）。**不要用 dev server** —— 它有 HMR 与未压缩模块，数字没有意义。
- 三个预算（规格 §8）：
  - 搜索输入 → 列表稳定显示 **P95 ≤ 200ms**
  - 气泡打开 **≤ 150ms**
  - 月回顾计算 **≤ 100ms**（预热后 20 次）
- **记录机器与数据规模**（规格明确要求），并把 `--seed`／`--anchor` 一并写进报告，让每个数字可复现。样本怎么灌进浏览器见 fixture 头部注释（写 `localStorage` 的两个键）。

### 2. 不达标时的处理顺序（不能反过来）

规格 §8 写得很清楚：**「若不达标先查重复计算，再决定分页或虚拟列表」**。

1. 先找重复计算／重复扫描：每行扫全量数组、每次状态更新重建索引、每像素重渲染、每帧重算派生值。
2. 确认确实是「渲染量」问题之后，才考虑分页或虚拟化。
3. **虚拟化必须保留**：键盘遍历、最近推进定位、拖拽来源、屏幕阅读器名称。**做不到就不要虚拟化** —— 宁可如实记录为未达标，也不要为了数字牺牲可达性。

### 3. 全模块缩放与响应性回归（AC14）

- 100／150／200% 与 960／1200 宽度下核心路径可完成；浅／深色都要。
- **P4-08 新增的回顾页是重点**：图表与「始终可见的等价数值表」在 200% 与窄宽下最容易坏。
- axe 自动检查 **＋ 视觉检查**。规格要求截图至少覆盖：气泡上下边缘、长课程、截止空／满状态、三种回顾、设置保存错误、恢复确认。
- **用性能样本跑长列表路径**（1,000 任务），不要只用几条假数据 —— 缩放下「入口被挤出屏幕」这类问题只在真实规模下才出现。

### 4. 错误与慢写回归（AC16）

规格 §8 的三段要求，逐条确认已有覆盖并补齐缺口：

- 保存中显示动作进度；失败用**局部持续错误 + 重试**；设置失败保留「未保存」与重试，**不被旧请求的成功覆盖**。
- 网络导入按**请求编号**丢弃过期结果；取消读取不误报「最终数据库提交已取消」。
- 备份逐条检查保留只读协议；加缓存与可见项调度时以 `path+mtime+size` 为缓存键，**恢复确认前重新 inspect**；不得把缓存成功结果当作来源文件永久有效，也不并行绕过原生数据操作队列。

已有覆盖在 `src/lib/settings.test.ts` 与原生隔离测试里。**不要放宽既有断言**来让它变绿。

```powershell

```

外加**生产构建下的性能测量**（数字、机器、种子、数据规模都要进报告）。

- 本机 `npm run check` 四步全绿（2026-10-16 实测：build dist JS 465.45 kB / CSS 81.24 kB、Vitest 291/24、Playwright 37、Rust 38；本包会改这些数字，以你实测为准）。

- 若 `test:native` 出现 `error copying object file … 拒绝访问 (os error 5)`：是 `src-tauri/target/debug/incremental` 的增量缓存问题，删该目录即可，不影响结果。
